# Stage 05c — versioned distance evidence registry (#41, #43, #46, #67)

This is a scientific review gate, not a new distance catalogue. Preserve all adopted values, raw methods, errors and membership definitions. The existing SQL freshness guards remain authoritative; no migration or physical refresh is required. The registry is a small Python source module shipped with the backend, reviewed through normal Git history. No public write API is provided.

## Two independent review axes

The value key is SHA-256 over a versioned canonical JSON payload: PGC, raw observed mu and dist, Table 1 method, Table 6 method/reference, source catalogue/name, physical adoption basis, and current calculation formula version. The interval key additionally includes raw e_mu and propagated-error basis. Numbers are normalized as finite decimals so a CSV string and a SQL Decimal with trailing zeroes match. Text is exact (empty/NULL normalized). The global revision number is deliberately not hashed: unrelated changes should not revoke a scientific review. Current snapshot validity and computed revision remain required in the existing SQL queries. The source-paired audit rechecks the adopted numerical value and propagated errors on every use.

Each review record must identify the actual PGC, axis, fingerprint, matching bibliographic reference, source locator, reviewer, date, decision and note. `VERIFIED` means an explicit, independently reviewed record; it is not derived from an indicator code, reference presence, small error or REVIEW_READY. The initial registry contains only ten interval HOLD records from Stage 05b (2023Ap.....66....1K), no approvals. Review-ready status is unchanged. A missing record is NOT_REVIEWED; a mismatched record is STALE; malformed source metadata gives UNAVAILABLE; a purported approval that fails the existing science gate is BLOCKED. HOLD blocks the relevant axis. A stale record never unlocks anything.

Value approval requires current source-paired REVIEW_READY individual modulus and a valid computed revision. The interval additionally requires value approval and exact traceability of the propagated errors. Changing e_mu invalidates interval evidence independently. Physical 3D eligibility also requires valid ICRS coordinates and excludes PGC 5064336 (the Milky Way). It is not an assertion of binding, group membership validation or independence of statistical errors. A later scene must additionally require accepted member status and an eligible centre; pair intervals must use verified uncertainty flags, not traceability alone. A root's actual gate is exposed in scene_center. Existing figures and numerical measurements are not changed by this stage.

## Evidence workflow

Use the Stage 05a read-only audit CSV, then the Stage 05c installer --audit --input <csv> --output <new csv>. The latter does not access the database; it verifies a coherent test snapshot and computes review fields. Review individual source rows (object identity, exact adopted modulus, method, calibration, reference and uncertainty), then propose explicit registry entries for human scientific review. Do not bulk-promote all TRGB or all REVIEW_READY entries. For ten suspicious error rows the Stage 05b note identifies the suspected issue; no numerical correction or source-level approval is made here. BTF/geom/spec classifications remain unchanged pending source investigation.

The initial test snapshot has 1,677 objects, 10 matching interval HOLDs, no verified distances or intervals. Source evidence and database integration must still be reviewed before enabling a production 3D viewer.
